# Обновление редактора контуров

Основа: `main`, коммит `2049acf`. Изменения редактора и каталога
подготовлены в ветке `codex/editor-and-club-catalog` для просмотра через
pull request. Слияние в `main` запускает существующий workflow GitHub Pages.

## Получение изменений в WSL

После слияния pull request в `main`, при чистом рабочем дереве:

```bash
cd ~/projects/nsu-activity
git status
git pull --ff-only
npm ci
npm test
npm run build
npm run lint
npm run dev
```

Если есть незакоммиченные изменения, сначала сохраните их. Перед проверкой
редактора экспортируйте текущую разметку из браузера: localStorage не входит
в Git. Локальная копия WSL не обновляется автоматически.

Для тестов нужен Node.js 24, как в существующем GitHub Actions workflow.
Новые зависимости не добавлены, package-lock.json не меняется.

## Какие файлы меняются

- `src/components/FloorPolygonEditor.tsx`: импорт, выбор политики конфликтов,
  безопасное редактирование, перетаскивание и добавление/удаление вершин,
  восстановление черновика и сообщения об ошибках хранения.
- `src/data/roomPolygons.ts`: типы, проверка структуры JSON и геометрии,
  объединение по составному ключу «здание, этаж, номер аудитории».
- `tests/roomPolygons.test.ts`: проверка исходных шести контуров,
  некорректных данных и объединения без потери других этажей/зданий.
- `package.json`: команда `npm test` на встроенном тестовом раннере Node.js.
- Этот файл: инструкция и ограничения.

## Как пользоваться

### Поиск границы по клику

В редактор добавлен режим «Найти контур по клику»:

1. Укажите номер аудитории.
2. Нажмите «Найти контур по клику».
3. Нажмите внутри нужного помещения, вдали от зелёных стен.
4. Проверьте предложенную красную границу, при необходимости поправьте вершины.
5. Нажмите «Сохранить контур». Для публикации по-прежнему нужен экспорт JSON.

Поиск выполняется в браузере по оригинальному PNG, без Python и сервера.
Он не распознаёт номер аудитории и не создаёт помещения или мероприятия
в справочнике. Через открытую дверь могут объединиться соседние комнаты:
сравнение со стенами остаётся обязательным.

До нажатия «Сохранить контур» результат — только черновик. Сохранённые
контуры не меняются автоматически. Если черновик уже содержит точки,
перед заменой запрашивается подтверждение. Отказ, ошибка или отмена поиска
сохраняют текущий черновик. При смене этажа или закрытии редактора поиск
отменяется. Предложенный контур, сохранённый в черновике, восстанавливается
как и ручная разметка.

Обработка работает в Web Worker; поиск можно отменить кнопкой. Слишком
большие области, неоднозначные границы, отверстия и чрезмерно сложные
контуры отклоняются. В этих случаях доступен режим «Точки вручную».
Режим рассчитан на текущие планы с зелёными стенами; произвольные другие
изображения не поддерживаются.

### Работа с файлами и сохранёнными контурами

1. Откройте этаж и редактор. Если записи localStorage ещё нет, редактор
   загрузит опубликованный JSON. Если локальная разметка уже существует,
   она используется как есть. Кнопка «Загрузить опубликованные контуры»
   позволяет явно объединить её с опубликованной версией.
2. «Импорт JSON» принимает массив в существующем формате. Весь файл
   проверяется до изменения данных. При отличающихся контурах с одинаковым
   составным ключом выберите сохранение текущих версий или замену из файла.
   Выбранная политика применяется ко всем конфликтам этого импорта;
   остальные контуры добавляются. Импорт можно отменить.
3. Нажмите номер сохранённой аудитории под планом. Оригинал остаётся синим,
   редактируемый черновик отображается красным. Номер существующей аудитории
   при редактировании не меняется: это предотвращает случайное переименование.
4. Перетаскивайте вершины. Нажатие на ребро вставляет точку с проекцией на
   это ребро. Выберите вершину и нажмите «Удалить выбранную вершину» или
   сфокусируйте её клавиатурой и нажмите Delete. Удаление оставляет минимум
   три точки. Кнопка со стрелкой убирает последнюю добавленную точку.
5. «Сохранить контур» обновляет сохранённый набор; «Отменить изменения»
   удаляет только черновик. Черновики независимы для каждого этажа и
   восстанавливаются после смены этажа, закрытия редактора и перезагрузки.
6. «Экспорт JSON» выгружает сохранённые контуры всех этажей и зданий.
   Он не включает незавершённый черновик. «Скачать черновик» сохраняет
   отдельный файл резервной копии, который не предназначен для публикации
   и не импортируется кнопкой «Импорт JSON» в этом этапе.
7. Для публикации геометрии замените `public/data/room-polygons.json`
   экспортированным файлом, проверьте сборку и отправьте изменения в GitHub
   привычным способом. Просмотрщик продолжает читать опубликованный файл,
   а не localStorage редактора.

Координаты остаются в системе SVG 0–1000, исходные PNG не меняются.
Не допускаются повторные вершины, выход за пределы плана, нулевая площадь,
пересечения и самокасания контура. Геометрия автоматически не исправляется.
Неизвестные редактору здания/этажи сохраняются при импорте и экспорте,
но редактировать можно только имеющиеся планы корпуса № 1.

При повреждённой записи localStorage исходная строка не перезаписывается
при открытии. Перед явной заменой создаётся резервная запись с суффиксом
`-recovery-<время>`. При отказе браузера в записи показывается ошибка;
последние изменения могут оставаться только в памяти — скачайте контуры
и черновик до закрытия. Одновременное редактирование в нескольких вкладках
в этом этапе не поддерживается.

## Проверено

- `npm test`, `npm run build`, `npm run lint`.
- В Chromium через Playwright: исходная загрузка, сохранение оригинала при
  выборе редактирования, перетаскивание при 100% и 150%, вставка/удаление
  вершины, отмена и сохранение, восстановление после смены этажа,
  закрытия редактора и перезагрузки страницы.
- Отмена импорта и обе политики конфликтов; отклонение файла с ошибочной
  записью без частичного импорта; экспорт всех шести исходных контуров.
- Отображение исходных контуров в просмотрщике на этажах 0–5.
- Повреждённое хранилище, резервное копирование при замене и ошибка квоты
  записи: неуспешное сохранение не очищает черновик.
- Браузерный поиск по клику даёт те же точки, что Python-инструмент,
  на всех семи подтверждённых полуавтоматических контурах. Проверены
  масштаб 150%, ошибочная точка на стене, отказ заменить черновик,
  отмена поиска, смена этажа во время поиска и явное сохранение.
- Весь поиск идёт по исходному PNG: синие и красные SVG-наложения
  не попадают в анализ. Публикуемый набор из 13 контуров не меняется.

3. Эксперимент с автоматической оцифровкой одного этажа: выделение стен,
   восстановление замкнутых областей и распознавание номеров. Предложения
   компьютерного зрения должны проверяться человеком, особенно у дверей,
   лестниц, коридоров и подписей. Точность на всех этажах пока не оценена.
4. Унифицировать связи клубов и встреч, добавить источники данных,
   затем развивать фильтрацию и анализ активности на карте.

Новые клубы уже можно добавлять в `src/data/clubs.json`; встречи —
в `src/data/activitySessions.ts`, помещения — в `src/data/campusRooms.ts`.
Пока связи встреч используют `clubName`, поэтому названия необходимо
согласовывать вручную. Импорт геометрии не создаёт клубы или мероприятия.

## Повторяющиеся номера на плане

У разных физических помещений может быть один напечатанный номер.
У них отдельные внутренние идентификаторы; на плане показывается исходный
номер, а в списке — уточнение «область 1/2 на плане». Для изменения такого
помещения выберите конкретную область под планом. Ввод одного номера при
нескольких совпадениях не заменяет ни один из сохранённых контуров.
Импорт и экспорт сохраняют видимый номер и связь с записью помещения.
